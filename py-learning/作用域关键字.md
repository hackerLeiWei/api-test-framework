作用域（Scope）和相关的关键字（`global`、`nonlocal`）是 Python 中**决定“变量在哪儿能被看到”以及“赋值时修改的是哪一份数据”**的核心规则。

结合你之前对函数参数（位置/关键字）的深究，我们可以把作用域理解为**变量在函数中的“领土”**。下面我为你彻底讲透，并重点区分最容易踩坑的 `global` 和 `nonlocal`。

---

### 1. 作用域的层级（LEGB 规则）

Python 查找变量时，遵循 **LEGB** 原则，从内到外一层层找，找不到就报 `NameError`：

| 层级 | 全称 | 说明 | 举例 |
| :--- | :--- | :--- | :--- |
| **L**ocal | 局部作用域 | **函数内部**定义的变量。 | `def foo(): x = 1` 中的 `x` |
| **E**nclosing | 嵌套外层作用域 | **外层嵌套函数**的局部作用域（闭包环境）。 | `def outer(): y=2; def inner(): ...` 中的 `y` |
| **G**lobal | 全局作用域 | **当前模块（.py文件）**顶层**定义的变量。 | 文件顶部的 `z = 3` |
| **B**uilt-in | 内置作用域 | Python 内置的函数和异常名。 | `print()`、`len()`、`ValueError` |

---

### 2. 核心易错点：赋值即声明

在 Python 中，**只要你在函数体内对某个变量进行了赋值（`=`），Python 就默认把它当作该函数的局部变量**，除非你特意用关键字声明。

看这个经典翻车案例（结合你学的异常处理）：

```python
x = 100  # 全局变量

def test():
    print(x)  # ⚠️ 这里会报错吗？
    x = 200   # 这里对 x 赋值了

# 调用 test() 会抛出 UnboundLocalError: local variable 'x' referenced before assignment
```
**原因**：因为函数内有 `x = 200`，Python 在编译时就把 `x` 标记为“局部变量”。当执行 `print(x)` 时，局部变量 `x` 还没被赋值（赋值在后面），所以报错，**它压根不会去看全局的 `x=100`**。

---

### 3. `global` 关键字（跳出函数，修改全局）

如果你想在函数内部**修改**全局变量，必须先用 `global` 声明。

```python
x = 100

def test():
    global x   # 声明：我要动的是全局的 x
    print(x)   # 100
    x = 200    # 修改全局变量

test()
print(x)       # 200 （全局被改了！）
```

> **警告**：滥用 `global` 会让代码变得极难调试（因为谁都能改这个变量）。结合你之前学的**卫语句**和**异常处理**，在工程中，我们更推荐把全局变量作为参数传入函数，而不是在函数内部 `global` 修改。

---

### 4. `nonlocal` 关键字（跳出局部，修改嵌套外层）

`nonlocal` 是 `global` 的“近亲”，但它只用于**嵌套函数**中，用来修改**外层嵌套函数（Enclosing）**里的变量。

```python
def outer():
    y = 10  # 这是外层局部变量

    def inner():
        nonlocal y  # 声明：我要改的是外层 outer 里的 y，不是全局的
        y += 1      # 修改外层变量
        print(y)    # 11

    inner()
    print(y)        # 11 （外层确实被改了）

outer()
```

**特别注意**：`nonlocal` **不能**用于全局变量，也不能用于内层函数中不存在的变量，否则报语法错误。

---

### 5. 结合你的知识库（位置参数与异常）做区分

| 场景 | 要不要用关键字 | 理由（结合你学的） |
| :--- | :--- | :--- |
| **读取全局变量**（不修改） | **不需要** `global` | 因为 LEGB 规则会自动往外找，像读取 `PI = 3.14` 这种常量，直接 `print(PI)` 即可。 |
| **修改全局变量**（重新赋值） | **必须** `global` | 如果不写，Python 会创建一个重名的局部变量，全局变量纹丝不动，而且容易触发 `UnboundLocalError`。 |
| **在嵌套函数中修改外层变量** | **必须** `nonlocal` | 如果不写，内层函数的赋值只会创建内层自己的局部变量，外层不变。 |
| **修改可变对象（如列表、字典）的内容** | **不需要** `global` 或 `nonlocal` | 比如 `my_list.append(10)`，这里没有重新赋值（没有 `=`），只是调用方法修改对象内容，不会触发作用域问题。 |

**代码验证最后一点：**
```python
my_list = [1, 2]

def test():
    my_list.append(3)  # ✅ 不需要 global，因为没有给 my_list 重新赋值

test()
print(my_list)  # [1, 2, 3]
```

---

### 6. 快速总结：什么时候该用哪个？

1.  **只用不赋值**（读）：不需要任何关键字，Python 自动往外找。
2.  **在函数最外层给变量赋值**（如 `x = 1`）：默认创建**局部变量**。
3.  **想修改全局变量**：在函数里写上 `global 变量名`。
4.  **想在嵌套函数里修改外层函数的变量**：在内层函数里写上 `nonlocal 变量名`。
5.  **函数内部想删除一个变量**：用 `del 变量名`，这属于作用域管理的一部分。

---

### 7. 补充：`try-except` 不改变作用域

这里有一个重要冷知识（结合你之前问的 `try`）：`if`、`for`、`while`、`with`、`try-except` **不会**创建新的作用域。在它们内部赋值的变量，在外部依然能访问。

```python
try:
    result = int("123")  # 在 try 里赋值
except ValueError:
    pass

print(result)  # ✅ 123，能正常打印！因为 try 没有自己的作用域
```
**只有 `def`（函数）、`class`（类）、`lambda`（表达式）会创建新的作用域。**
